# Spec Delta

## Purpose

让维护者能够追踪一次发言从识别、模型处理、工具查询到语音输出及终止的结果，区分完成、失败和取消。以可查询记录和同条件对照报告解释行为与延迟，避免将模拟结果、查询垫话或作者机器数据当成本机证据。

## ADDED Requirements

### Requirement: OB-01 每回合可关联的终态记录
系统 SHALL 为每个受理回合记录会话与回合身份、时间、输入、最终回答、工具尝试、分段耗时及终态；失败或取消不得记为成功，未完成文本不得因此进入续聊记忆。

#### Scenario: 完成与取消分别记录
- **WHEN** 一个回合成功而另一个因接管取消
- **THEN** 查询得到各自的终态与原因，只有成功回合包含可恢复的完整问答

### Requirement: OB-02 工具执行与配额可检查
系统 SHALL 记录工具名称、执行次序、成功或失败、耗时和是否因配额或校验被拒绝，能区分实际尝试与未执行请求。

#### Scenario: 探针和配额核验
- **WHEN** 维护者查询一个使用探针或触发配额上限的回合
- **THEN** 能核实实际执行次数、结果与拒绝项，第四次请求不能被混记成第四次成功执行

### Requirement: OB-03 审计命令可查询
系统 SHALL 提供本机审计查询入口，支持按会话或回合检索，并让未找到记录、失败记录和成功记录有明确区别。

#### Scenario: 查询已知回合
- **WHEN** 维护者用会话或回合身份查询
- **THEN** 输出匹配记录的输入、结果、工具摘要、耗时和终态，不混入其他会话记录

### Requirement: OB-04 可解释的延迟口径
系统 SHALL 分别记录识别、模型、工具、合成耗时及首个有效文字、首段声音指标，并说明测量起点；“查询中”或过渡语不算有效回答，客户端实际首音与服务端首音就绪不得混为同一指标。

#### Scenario: 生成和播放起点不同
- **WHEN** 首音频已在服务端就绪但浏览器稍后才开始播放
- **THEN** 报告分别保留两项结果，不用服务端耗时代替用户实际等待时间

### Requirement: OB-05 同条件基线比较
系统 SHALL 用本机同模型、同配置、同一批样本比较基线与 Agent 版本，保留原始测量、失败样本及统计摘要，以增加不超过 500ms 为优化目标。

#### Scenario: 实测有失败或超标
- **WHEN** 验收样本存在超时、失败或延迟增加
- **THEN** 报告不丢弃这些样本以美化结果，注明环境、样本数量和归因，作者约 0.9 秒仅能作为资料背景

### Requirement: OB-06 日志出口失败不伪造回合状态
系统 SHALL 将结构化回合终态与问答保存边界保持一致；附加 JSONL 输出失败必须被诊断，但不得撤销已经提交的完整问答或让用户重复提交。

#### Scenario: 问答保存成功而日志文件无法追加
- **WHEN** 业务存储已成功提交但附加日志输出失败
- **THEN** 用户回合仍成功，维护者看到日志告警，审计的持久终态仍可查询

### Requirement: OB-07 可复核的整体验收
系统 SHALL 提供自动化检查和真实浏览器、云接口验收记录，覆盖鉴权、隔离、恢复、接管、取消、工具闭环、演出及性能；未执行项必须显式保留。

#### Scenario: 声称完成 M0
- **WHEN** 汇总本次交付验收
- **THEN** 每个范围有对应结果和证据，模拟测试不能替代真实探针、声音、形象或实际延迟验收
