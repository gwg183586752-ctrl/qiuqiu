# Spec Delta

## Purpose

让小糖在保持语音演出体验的同时，具备可验证且不会无限循环的工具调用能力。当前阶段仅使用时间探针证明调用闭环，并如实区分模型背景知识、尚未接入的知识检索和无法核实的实时足球信息。

## ADDED Requirements

### Requirement: AG-01 时间探针闭环
系统 SHALL 在 M0 只注册返回服务器当前时间的探针工具；验收必须证明真实模型发起调用、获得真实工具结果并据此给出最终回答。

#### Scenario: 真实探针问题
- **WHEN** 对真实模型提出需要查询服务器当前时间的问题并触发工具调用
- **THEN** 最终回答与本次执行的时间结果一致，回合记录显示真实工具调用，不能用硬编码回答冒充闭环

### Requirement: AG-02 实际工具尝试封顶
系统 SHALL 为每轮实际工具执行尝试设置 3 次上限，失败也占次数；单次模型响应包含多个调用时同样累计，未经注册或参数非法的调用不得执行。

#### Scenario: 第四次调用请求
- **WHEN** 本轮已有 3 次实际尝试而模型继续要求调用工具
- **THEN** 第四次工具执行不会发生，系统转向使用已有信息收尾

#### Scenario: 同一响应包含多项调用
- **WHEN** 模型一次要求的调用数超过剩余配额
- **THEN** 实际执行数不超过剩余配额，未执行项不会被伪装成成功结果

#### Scenario: 非法参数
- **WHEN** 工具名称未注册或参数不符合约束
- **THEN** 不运行工具，记录可诊断结果，并在有界流程内收尾而非无限纠错重试

### Requirement: AG-03 配额耗尽后仍有回答
系统 SHALL 在工具配额耗尽后安排不再执行工具的最终回答；最终回答不计作工具尝试，已有信息不足时必须说明不足。

#### Scenario: 三次工具均失败
- **WHEN** 实际尝试已达到上限且没有有效结果
- **THEN** 用户得到简短的能力不足或查询失败说明，而不是只有工具结果、无声等待或继续调用

### Requirement: AG-04 查询过程与有效回答分开
系统 SHALL 在工具查询期间显示查询状态，不将查询阶段的垫话、思考内容、工具参数或原始结果送入用户口播；最终有效回答仍支持增量生成和分句播放。

#### Scenario: 模型输出查询垫话
- **WHEN** 工具阶段产生“我查一下”等过程性文本
- **THEN** 页面保持查询状态，该文本不进入字幕、语音或有效回答首字计时

#### Scenario: 有效回答开始
- **WHEN** 查询结束并进入不再提供工具的收尾生成
- **THEN** 有效回答增量进入原有标签、切句与语音链路，保留正常表情动作语气

### Requirement: AG-05 足球人设与实际能力一致
系统 SHALL 保持小糖“元气、话少但暖”的人设并加入真诚足球迷身份；M0 可依据已有知识回答基础规则和历史背景，拿不准时说明，实时比分、赛程和当前积分必须说明尚未接入查询。

#### Scenario: 询问实时积分
- **WHEN** 用户询问当前球队积分、实时比分或尚需实时核实的赛程
- **THEN** 小糖说明当前无法核实，不编造数据，不声称调用不存在的知识或实时工具

#### Scenario: 基础足球背景
- **WHEN** 用户询问基础规则或历史背景
- **THEN** 小糖可以谨慎回答并表达不确定性，不虚构检索来源

### Requirement: AG-06 保护演出规则
系统 SHALL 保留课程原有六条演出规则：短句口语、受支持的表情标签、仅四个既定动作、中文语气标签、纯净文本及关系边界；每回复 1—3 句、1—3 个表情、至多 2 个动作。

#### Scenario: 真机演出回归
- **WHEN** 使用固定闲聊和足球对话样本比较基线与 Agent 版本
- **THEN** 回复保持短句、标签有效、动作未越界，不出现标签解释、Markdown 或拟关系话术，语音字幕与动作保持一致

### Requirement: AG-07 可取消且有界的处理
系统 SHALL 对模型和工具等待施加明确的处理期限，接受回合取消，阻止取消后的进一步调用和用户输出；期限与实际测量结果必须记录在配置及验收中。

#### Scenario: 工具等待超时或回合取消
- **WHEN** 处理期限耗尽或会话所有权已丢失
- **THEN** 停止继续执行工具和发送音频，按失败或取消记录回合，客户端不会永远停留在查询中

### Requirement: AG-08 选型有真实验证结论
系统 SHALL 留下真实接口下的流式文本与工具兼容性结论，覆盖标签顺序、最终回答、取消和延迟归因，并说明继续使用 SDK 或转向手写循环的原因。

#### Scenario: 验证发现延迟超目标
- **WHEN** 真实工具回合相对同条件基线增加超过 500ms
- **THEN** 报告超标及模型、网络、编排或 SDK 归因，不只凭超标就断言 SDK 不兼容，也不将目标未达隐去
