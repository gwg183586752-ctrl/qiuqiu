# Spec Delta

## Purpose

让维护者能够在当前 Windows 电脑上复现启动、识别配置和依赖问题，并在接入真实对话前验证持久存储能力。诊断结果必须区分已验证能力、可恢复的向量扩展缺项和阻止服务启动的错误。

## ADDED Requirements

### Requirement: RT-01 可复现的本机启动
系统 SHALL 提供明确的安装、启动、健康检查、类型检查和测试说明，并记录实际运行时及锁定依赖。健康检查不得泄露凭证或对话内容。

#### Scenario: 从项目说明启动
- **WHEN** 维护者按说明安装锁定依赖并提供有效配置
- **THEN** 本机服务可启动，健康检查返回就绪状态，记录的命令与实际入口一致

#### Scenario: 运行时不兼容
- **WHEN** 当前运行时不满足选定依赖的兼容条件
- **THEN** 启动或安装诊断说明版本冲突与可选解决路径，不假装验证通过

### Requirement: RT-02 必需配置缺失即拒启
系统 SHALL 在接收业务连接前校验 M0 必需的云接口配置和访问口令；缺失项必须以不含密钥值的形式报告。尚未接入的知识库和实时数据服务凭证不得成为启动条件。

#### Scenario: 缺少必需配置
- **WHEN** 必需凭证或模型配置缺失且不存在明确默认值
- **THEN** 服务拒绝进入业务就绪状态，并仅指出配置项名称

#### Scenario: 未配置后续里程碑服务
- **WHEN** M0 配置完整但未提供知识嵌入或实时足球服务凭证
- **THEN** M0 仍可启动并使用其已经注册的能力

### Requirement: RT-03 原生存储可诊断
系统 SHALL 提供可重复的本机诊断，证明写入的数据可在重新打开存储后读取，并独立报告 1024 维向量扩展的加载与最小查询结果。

#### Scenario: 存储与向量诊断成功
- **WHEN** 在本机执行诊断
- **THEN** 记录运行时与平台，关系数据跨重新打开保持一致，已知向量样本返回预期近邻

#### Scenario: 仅向量扩展不可用
- **WHEN** 关系存储可用而向量扩展加载或查询失败
- **THEN** 报告向量验证未通过及原因，允许 M0 会话能力继续推进，不将未验证的向量能力标为可用

### Requirement: RT-04 存储升级保护已保存数据
系统 SHALL 在启动时建立或按顺序升级存储结构，保留既有会话和消息；迁移失败或遇到无法支持的新版本结构时必须拒绝业务启动，不自动清空或降级数据。

#### Scenario: 重复启动
- **WHEN** 已有兼容数据的服务再次启动
- **THEN** 已完成问答保持不变，初始化不重复生成业务数据

#### Scenario: 升级失败
- **WHEN** 存储升级中断或结构版本超出当前程序支持范围
- **THEN** 服务报告错误并保留原数据，不把半迁移状态作为正常就绪状态

### Requirement: RT-05 后续数据能力预留
系统 SHALL 在 M0 的存储结构中预留消息打断标记和知识、实体、审计数据的归属；预留结构不得对用户宣称已经具备知识检索或实时比分能力。

#### Scenario: 新建 M0 存储
- **WHEN** 完成初始建库
- **THEN** 预留结构可被检查，M0 消息的打断标记保持未打断，后续业务数据为空

### Requirement: RT-06 验证结果区分真实与模拟
系统 SHALL 明确区分无需云调用的自动化测试和使用真实云接口的验证；模拟结果不得被记录为模型权限、音质、工具兼容性或网络延迟的实测证据。

#### Scenario: 模拟测试通过
- **WHEN** 维护者运行注入模拟云适配器的测试
- **THEN** 报告标明模拟模式，真实云验证仍保留自己的结果或未执行状态
