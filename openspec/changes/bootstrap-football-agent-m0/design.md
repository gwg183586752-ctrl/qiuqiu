# Design

## Context

动机见 proposal 的 Why。规划开始时仓库没有应用、依赖清单或既有自动化测试；另一 worktree 只有不同路线的设计草稿，不能继承为本项目接口。适用术语和决策为 GLOSSARY 与 ADR-0001—0004。六份能力 delta 是本变更的行为契约，总规格 spec.md 提供用户故事视图。

本机已读到 Windows x64、Node 22.20.0、16GB 内存与 RTX 4060 Laptop；课程的 Node 24 和“没有独显”是作者环境。用户已有 MiMo 按量 API 凭证，但具体模型权限、真实延迟和 SDK 接入尚未实测。

规划后用户于 2026-10-24 明确授权 goal、implement 与真实验收，应用已按这些契约进入实施。实际版本、接口、测试和测量结果见 `docs/implementation/`，tasks.md 为唯一进度来源。tracker 未配置，逐票材料维持本地，不自动发布工单。

## Goals / Non-Goals

**Goals:**

- 先得到可比较的完整语音演出基线，再改变大脑，保证 Agent 与手写实现对下游透明。
- 持久会话、活跃连接和对话回合分别建模，定义迟到事件、接管和提交的确定结果。
- 以一个主集成边界验证业务行为，补充必要的浏览器演出与真实云证据。
- 依赖和模型以官方兼容性及实机结果锁定；诊断能明确区分阻塞错误与向量能力降级。

**Non-Goals:**

- M1 知识摄取/检索、M2 足球数据、M3 用户说话打断、M4 新动作及最终角色定制。
- 账号体系、公网或局域网部署、聊天历史列表、精准音素口型、逐字字幕。
- 本地模型服务、Python 应用、Docker、ORM、后端框架或完整遥测平台。
- 未经配置与粒度审阅就发布 issue、创建标签或修改项目 agent 配置。

## Decisions

### 1. 运行与模块边界

采用单包 TypeScript；React 管页面，Three.js/VRM 管演出，Node 原生 HTTP 与 ws 管本机健康检查和连接。配置在业务启动前加载并校验；浏览器只拿演示共享口令，不拿云密钥。测试通过依赖注入使用 fake 云适配器，真实运行不提供面向普通用户的假回答模式。

模块按业务职责划分：网关、会话协调、回合管线、MiMo 适配器、Agent 编排、演出标签/切句、持久存储、审计。浏览器分录音、连接、播放队列、角色表达、页面状态。核心接缝是回合管线中的“大脑流”：输入上下文和取消信号，输出可展示的回复增量及内部观测事件。

优先在现有 Node 22.20.0 验证兼容集合；若依赖确需 Node 24，记录证据后采用项目约定版本，不默认切换其他项目的全局运行时。AI SDK 路线明确使用 6 的文档和匹配 provider，不能把课程 provider 的 ^1 或官网最新版本原样混装。具体补丁版本在实施时锁定。

### 2. 新建协议契约

下表是新基线的拟定契约，不是假称已存在的课程“8 个事件”。基线确定后，Agent 阶段保持该边界稳定。所有业务事件包含协议版本与必要身份；回合事件带 sessionId、connectionEpoch、turnId，分段事件另带 segmentId 与 sequence。

| 方向 / 事件 | 输入或输出含义 | 约束 |
|---|---|---|
| 升级请求 | 共享口令、可选会话标识 | 验证先于会话查找/创建；地址日志脱敏 |
| 客户端 hello | 协议版本、支持的表情集合 | 只作为能力提示，取服务端允许集合交集 |
| 服务端 session.ready | 会话标识、连接代次、是否新会话 | 客户端持久保存标识；只在新会话安排开场白 |
| 客户端 turn.submit | 回合标识、音频及真实格式 | 一个连接只受理一个活跃回合；校验格式与大小 |
| 服务端 turn.state | 识别、思考、查询、合成等状态 | 状态不当作有效回答或字幕 |
| 服务端 transcript | 本轮识别的定稿文本 | 用于调试/回合关联，不增加历史列表 |
| 服务端 speech.segment | 分句纯文本、表情动作元数据 | 含序号；语气指令不显示在字幕中 |
| 服务端 speech.audio | 分段音频块、格式与终止标志 | 初版采用明确编号的消息载荷，按序排队；不得串回合 |
| 服务端 turn.done | 已成功提交的回合完成结果 | 不代表浏览器已经播放完毕 |
| 客户端 playback.done / metric | 播放完成和客户端观测 | 只影响当前连接播放状态/观测，不决定问答是否提交 |
| 服务端 turn.error | 可理解的终止原因 | 清理当前回合，技术详情只进脱敏审计 |
| 服务端 session.replaced | 会话已经由其他页面继续 | 旧页面停止录音、播放及自动重连 |

畸形消息在边界拒绝。录音时长、消息大小、外部等待期限使用有限配置并记录于使用说明；具体数值由真实接口 spike 得出，验收依据配置值而非写死假设。关闭/重连不自动重提旧录音；用户再次说话形成新的回合。

### 3. 浏览器和语音管线

客户端状态区分未连接、等待声音激活、待机、录音、处理中、播放中、被接管和可恢复错误。录音按钮只在待机或录音时开启对应操作；后端生成完但音频未播完仍不能开始新录音。

浏览器采集的格式必须真实转换为 MiMo 支持的 wav/mp3，不能把 WebM 直接标为 wav。不新增 Python 或外部转码服务；采集与编码在浏览器完成，相关兼容性纳入真实 ASR 验证。

生成文本先解析跨块标签，再切句；字幕使用纯文本，表情动作成为独立元数据，中文语气指令仅送入已验证的 TTS 表达入口。合成与播放都保持句子顺序；可边接收边播音频块，但分句字幕与该句实际开始播放对齐。音量驱动基础嘴部开合，停止、失败或接管时归零。

浏览器可能阻止首次自动播放。工程补全：复用既有按钮先激活音频，再播放本次新会话开场白，之后才能开始录音；不新增页面、账号步骤或常开麦克风。恢复会话不安排开场白或历史音频。相关依据见 MDN 自动播放指南。

### 4. 数据结构与完成边界

使用单文件 SQLite、直接 SQL 与递增结构版本；迁移在事务中完成，未知新版本和迁移错误拒启。备份应在关闭连接或通过一致性备份接口完成，不能在写入期间仅复制主文件而忽略 WAL。

| 数据对象 | 最小内容与约束 |
|---|---|
| 会话 | 服务端高熵标识、创建时间、开场白已安排状态；不等同账号 |
| 回合 | 全局或会话内唯一回合标识、会话归属、开始/终止时间、状态和原因、问题/完整答案、分段耗时 |
| 消息 | 自增序号、会话/回合归属、角色、内容、创建时间、预留打断标记；同一回合同一角色唯一 |
| 工具尝试 | 回合、调用次序、工具名、脱敏参数/结果摘要、是否实际执行、状态和耗时 |
| 知识块与实体预留 | 来源/外部标识、内容或名称、基础元数据；本期为空，不建立摄取或检索功能 |
| 审计与向量诊断 | 回合审计可查询；1024 维向量诊断独立于普通会话启动条件 |

受理回合时先持久登记身份，避免重提和服务重启触发同一回合重复云调用。启动时将遗留处理中回合终止为中断，不自动重跑。该记录不是对话消息，未完成输入仍不能注入历史。

完整回复和全部语音合成成功后，在短事务中重验连接所有权并写入一对消息、完整答案和成功终态；提交成功后发送 turn.done。SQLite 失败就不发送成功，JSONL 追加失败只产生诊断告警，不能撤销成功问答。窗口取最近 12 条普通完整消息再恢复正序；固定开场白不占问答窗口。

### 5. 单页面所有权与取消

每次接管递增连接代次，并将新连接设为该会话的唯一所有者。旧连接终止信号只取消其自己的回合。旧关闭回调、云返回、TTS 输出及提交路径均检查归属，不能清除或覆盖新连接。

接管和最终提交串行化：若提交先完成，新页面可恢复该整轮；若接管先完成，旧回合永不提交。浏览器也按连接代次和回合身份丢弃过期事件。取消不承诺云服务一定停止计费，但保证本地后续执行、提交和播放已失效。

选择单活跃页而非共享多页并发，以减少历史交错与播放冲突；选择完整回合保存而非半句记忆，以符合 M0 边界并给 M3 留出明确后续变更。

### 6. 工具阶段与回答阶段

优先 AI SDK 6，spike 失败且问题确属其兼容/编排时使用同构手写循环。工具注册包含名称、参数约束、执行器和观测结果；M0 唯一工具为 get_server_time，按明确时区返回可验证时间，不引入其他数据源。

工具阶段的模型文本全部留在内部，只向浏览器发送查询状态。实际工具尝试使用独立计数器，串行执行，失败计数；一个响应的多个调用按顺序消耗余额，超额或非法项返回受控结果。非法调用不无界重试；总处理期限耗尽就终止。

最终回答阶段移除工具定义，使用已有对话与工具结果增量生成；不能只发 tool_choice: none，因为 MiMo 当前文档只保证 auto。即使工具阶段模型不发起工具调用，也进入无工具的最终回答阶段，保证不会先播出随后又需要撤回的文字。此方案可能增加一次模型请求，这是选择“只播有效回答”的明确代价，必须被延迟报告解释。

最终回答仍遵守原有六条演出规则。普通闲聊走“判定无需工具→最终回答”；探针问题走“模型调用→执行结果→最终回答”。达到 3 次实际尝试后仍保留一次收尾生成机会，不把 stepCountIs(3) 等同于工具配额。

spike 覆盖匹配 provider 版本、schema 字段、同响应多工具、流式参数拼装、工具前文本、移除 tools 的最终请求、取消、thinking 配置及 reasoning_content 回传；记录实际请求契约但不得记录凭证。模型按账户实际权限选择，不能假定 ultraspeed 可用。

### 7. 人设与当前能力

保留课程六条演出规则原文、服务端固定开场白、小糖身份与冰糖音色。新增足球迷背景；M0 提示词按当前工具表编译能力说明，不引用尚未注册的 search_knowledge 或实时比分工具。背景知识可谨慎回答，实时数据明确无法核实；不把未知事实包装成检索结果。

### 8. 主测试接缝与验收

主接缝为真实 WebSocket 网关：测试连接真实服务，使用临时真实 SQLite，仅把外部云适配器替换为可控 fake。通过协议事件、音频顺序、恢复后的回答输入/结果和审计查询验证外部行为，不依赖内部函数调用顺序或为每层建一套 mock。

浏览器端另用少量 Playwright 测试验证按钮状态、音频激活、字幕队列、接管停止重连及基础演出；真实云样本验证权限、音质、probe 真实性与性能。当前没有可沿用的本仓测试，课程 node:test + fake adapter 只是设计参照，不能称为现有测试资产。

优先覆盖故障注入：SQL 事务失败、JSONL 写入失败、工具异常、TTS 中断、重复 turnId、旧连接晚关闭、接管与提交竞态、字幕标签跨分块。测试契约而非截图像素或组件实现细节。该接缝方案随拆票清单交用户审阅。

### 9. 指标与回归

服务端使用同一单调时钟记录接受完整录音到识别结束、各模型/工具/合成区间、首个有效回答字符、首音就绪和终态。客户端单独记录结束录音到实际首音的时长；不把两台时钟的时间戳直接相减，不将思考内容或状态计作首字。

先固定模型、配置、样本、预热及重复次数，保存基线原始记录，再用相同条件比较 Agent。报告中位数、尾部、失败率和完整样本，区分普通问题与时间探针。+500ms 是优化目标；超标保留问题并归因，不用手写循环掩盖网络/模型固有成本。

## Risks / Trade-offs

- 原生扩展或运行时不兼容 → 在独立诊断票先验证；SQLite 驱动失败阻塞持久会话，只有向量扩展失败则记录降级，不引入新数据库服务。
- 两阶段 Agent 增加模型请求 → 工具阶段只做短决策，真实测量其开销；功能正确与延迟目标分别报告。
- “已保存”早于“已听完” → 遵循已确认回合边界；前端仍等播放完成才开放录音，恢复不重播音频。
- 角色授权与实际效果不同 → 保留官方来源、v1.0.1 元数据和许可证，真实浏览器验证表情及骨骼；元数据不替代渲染验收。
- SQLite 与 JSONL 无跨资源事务 → 以 SQLite 终态为审计事实，JSONL 是附加出口；不要为了日志失败重试已完成业务。
- 浏览器身份存储失败 → 显示不能可靠续聊的错误并阻止假称成功恢复；不把无法持久身份的页面当作已通过续聊验收。
- 原版代码与部分关联材料缺失 → 明确接口为本项目新设计；保留未来数据结构扩展能力，不声称已复刻未见过的实现。

## Migration Plan

当前无应用数据可迁移。按 tasks 的依赖推进：可启动服务与原生诊断、可见模拟闭环、真实语音基线、鉴权和会话、审计与 Agent、完整验收。原生诊断与可见基线可并行，兼容 spike 在基线完成后可与持久会话工作并行。

首次应用提交同步安装、运行和验证说明。存储迁移只向前，变更前做一致性备份；失败时回到兼容程序与备份的成对状态，不以删除数据库作为默认修复。原文档和既有 ADR 保留，本次能力 delta 在后续正式归档时再同步为主规格。

## Open Questions

以下只影响实现参数或外部验证结果，不重新打开已确认行为：

- 账户可用的具体 ASR/LLM/TTS 模型、thinking 模式及音频参数：真实接口票和兼容 spike 核定。
- 可安装的精确依赖补丁版本、Node 22 或项目 Node 24 路线、向量扩展状态：原生诊断核定并锁定。
- 录音长度、载荷大小、处理期限与样本数量的具体配置值：在接口验证时根据服务限制选定并写入证据。
- 测试接缝与票粒度已由用户确认；外部任务发布载体仍未配置，本次按本地 tasks.md 执行，不发布工单。
