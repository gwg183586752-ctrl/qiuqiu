# 01：从干净环境启动本机诊断服务

**What to build:** 维护者依照说明安装并启动本机服务，看到健康状态；缺少本阶段必需配置时，在调用云接口前得到清晰错误。

**Blocked by:** None（无前置依赖，可开始）

**Status:** draft — 待任务粒度、依赖和发布载体审阅

**Spec coverage:** RT-01、RT-02、RT-06、AC-01

**User stories:** US-01、US-02、US-39

## Acceptance criteria

- [ ] 实际 Node、包管理器与依赖版本已记录并锁定，安装和启动命令在本机验证通过。
- [ ] 开发服务及诊断入口只绑定回环地址，健康输出不含凭证。
- [ ] 本阶段必需配置缺失或格式不合法会拒启；M1/M2 未启用能力不要求凭证。
- [ ] 模拟模式与真实模式标识清楚；模拟健康不能被描述成云接口可用。
- [ ] 首次应用代码同时提供实际安装、启动、验证和停止命令。

## Implementation steps

以下细项与上一级任务清单中的 1.x 一一对应；进度统一在该任务清单记录，本票验收项用于确认行为。

1. 确认本机运行时与项目采用版本，建立单包 TypeScript 工程及锁文件；验证实际安装与类型检查成功，并记录版本。
2. 建立回环 HTTP 服务及健康入口；验证本机请求成功且监听地址不是所有网卡。
3. 建立按启用阶段校验的配置入口和不含值的错误信息；验证缺少必需项拒启、可选未来项缺失仍可启动。
4. 提供显式 fake/real 适配器选择并在诊断输出标注；验证 fake 模式不需要也不会调用真实云凭证。
5. 建立从公开入口启动和关闭服务的行为测试入口；验证健康、错误配置和资源释放结果。
6. 补齐维护说明中的实际安装、运行、检查和停止命令；从新终端逐条执行并保存本机诊断结果。

## Verification

公开健康入口与进程退出行为；不测试内部配置函数的组织方式。

每项结论注明环境、输入、结果与证据类型。模拟通过不能代替真实接口或浏览器观察；故障和未验证项须保留。完成本票时同步其使用说明与验证命令。

## Scope boundary

不接入真实语音、持久会话或 Agent。
