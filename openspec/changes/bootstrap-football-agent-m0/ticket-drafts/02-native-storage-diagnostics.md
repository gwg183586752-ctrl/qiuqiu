# 02：验证原生持久存储与向量扩展

**What to build:** 维护者通过诊断命令写入、重启并读回记录，分别看到 SQLite 和 1024 维向量查询结果，并能识别迁移失败。

**Blocked by:** #01 从干净环境启动本机诊断服务

**Status:** local implementation — 已获用户授权；进度以 ../tasks.md 为准，未发布外部工单

**Spec coverage:** RT-03、RT-04、RT-05

**User stories:** US-03、US-41、US-42

## Acceptance criteria

- [ ] SQLite 在当前 Windows、Node 和原生依赖组合下完成真实写入、关闭、重开、读取。
- [ ] 1024 维向量插入与检索有独立实测结果；失败时说明原因，不把模拟结果当成功。
- [ ] 关系存储失败阻塞相关应用启动；仅向量扩展失败时明确降级，可继续 M0 普通会话。
- [ ] 前向迁移具有版本与事务；失败保留原数据，未知更新版本拒启。
- [ ] 会话、回合、消息、工具审计及后续知识块/实体的最小结构和打断预留字段可检查，无知识业务。
- [ ] 一致性备份和恢复在临时数据上验证；不把删除数据库作为默认修复。

## Implementation steps

以下细项与上一级任务清单中的 2.x 一一对应；进度统一在该任务清单记录，本票验收项用于确认行为。

1. 核定原生驱动和扩展的实际可安装版本；验证当前 Node ABI 下加载结果，并将采用组合记入锁定说明。
2. 提供持久存储诊断命令，串起写入、关闭、重开和读取；验证临时库重启后数据相同。
3. 实现 1024 维向量诊断并分离关系存储与扩展结果；验证真实命中及仅扩展失败的降级输出。
4. 建立递增版本、事务迁移和最小预留结构；验证空库初始化与旧版示例库升级不丢数据。
5. 覆盖迁移中途失败和未知新结构版本；验证无部分迁移、无自动删库且拒启信息明确。
6. 提供一致性备份恢复操作与诊断说明；在临时数据库完成恢复并记录数据核对结果。

## Verification

执行真实诊断命令和临时真实数据库，不以 mock 证明原生兼容。

每项结论注明环境、输入、结果与证据类型。模拟通过不能代替真实接口或浏览器观察；故障和未验证项须保留。完成本票时同步其使用说明与验证命令。

## Scope boundary

不实现知识摄取、embedding 云调用、RAG 或用户会话页面。
