# 09：刷新和重启后继续各自的会话

**What to build:** 新会话播放一次开场白，随后完成的问答持久保存；同一浏览器刷新或服务重启后续聊，两个浏览器各自保持上下文。

**Blocked by:** #02 验证原生持久存储与向量扩展；#08 用共享口令保护本机连接入口

**Status:** local implementation — 已获用户授权；进度以 ../tasks.md 为准，未发布外部工单

**Spec coverage:** PC-01、PC-02、PC-03、PC-05、PC-08、PC-09

**User stories:** US-15、US-16、US-19、US-20、US-21、US-27

## Acceptance criteria

- [ ] 会话标识由服务端生成并由同源浏览器持久保存；未知标识不能被客户端指定成新身份。
- [ ] 两浏览器使用相同入口口令时仍拥有独立上下文，身份持久化失败会明确提示。
- [ ] 新会话只安排固定开场白“嗨，我是小糖，今天想聊点什么呀？”，恢复会话不重播开场白或历史音频。
- [ ] 完整回复及全部 TTS 成功后，问答成对保存；最近十二条完整普通消息按正确顺序恢复，开场白不占窗口。
- [ ] 历史窗口只限制模型输入，早期持久消息不会因此删除。
- [ ] 回合身份在云调用前登记，基础重提不重复调用；接管竞态与故障组合在后续票强化。
- [ ] 服务重启后可恢复已完成问答；遗留处理中回合按中断终止，不自动重跑。

## Implementation steps

以下细项与上一级任务清单中的 9.x 一一对应；进度统一在该任务清单记录，本票验收项用于确认行为。

1. 实现服务端生成身份及浏览器持久保存；验证未知标识重新分配、存储失败明确提示且不会假称已恢复。
2. 接通真实存储与会话恢复；通过双浏览器分别问答，验证上下文及返回内容没有交叉。
3. 实现新会话标记和固定开场白安排；验证首次播放一次，刷新、重开和重启恢复不自动重播。
4. 受理前登记回合身份，并在完整生成与全部 TTS 成功后事务保存一对消息；验证完成后重开数据库能恢复整轮。
5. 恢复最近十二条完整普通消息并保持正序；以超过六轮的历史验证窗口边界、开场白排除及旧数据保留。
6. 处理服务重启后的处理中回合与基础重复提交；验证遗留回合不自动执行、重复标识不增加云调用和消息。
7. 通过真实 WS 与临时 SQLite 测试续聊路径，补齐身份与历史说明；记录真实浏览器刷新、重开、服务重启的观察结果。

## Verification

真实 WS＋临时真实 SQLite；观察恢复后模型实际收到的上下文、公开响应与持久记录。

每项结论注明环境、输入、结果与证据类型。模拟通过不能代替真实接口或浏览器观察；故障和未验证项须保留。完成本票时同步其使用说明与验证命令。
