# 13：实测 SDK 与 MiMo 的工具流兼容性

**What to build:** 维护者运行一个有退出条件的真实诊断，看到模型调用时间探针、收到结果并形成最终回复，获得是否采用 SDK 的可复核结论。

**Blocked by:** #07 形成可重跑的基线验收和延迟报告

**Status:** draft — 待任务粒度、依赖和发布载体审阅

**Spec coverage:** AG-01、AG-03、AG-04、AG-07、AG-08、RT-06

**User stories:** US-28、US-29、US-31、US-38、US-40、US-42

## Acceptance criteria

- [ ] 诊断用真实账号、真实模型和真实服务器时间；记录实际依赖版本、模型、thinking 和协议选项。
- [ ] 核验流式工具参数、工具前文本、同响应多调用、工具结果回传及无工具最终请求的契约。
- [ ] 最终阶段确实不携带工具定义；不把 tool_choice: none 当作供应商保证。
- [ ] 启用思考模式时，必要的 reasoning_content 按供应商契约传递且不进入用户输出。
- [ ] 取消和有限期限有实际结果；当前账号或模型无法触发的行为标记未验证，不用模拟冒充。
- [ ] 诊断有成功/失败判据与采用结论；SDK 问题须归因后才考虑同构手写循环。
- [ ] 保留原始分段时长，不声称独立诊断已经达到集成应用的延迟验收。

## Implementation steps

以下细项与上一级任务清单中的 13.x 一一对应；进度统一在该任务清单记录，本票验收项用于确认行为。

1. 核定 AI SDK 6 与 provider 的匹配版本和 schema 契约；运行最小真实请求并记录采用版本与实际可用模型。
2. 建立输入问题→真实时间工具→结果回传→最终回答的可运行诊断；核对回答与本次时间结果一致。
3. 验证流式工具参数和工具前文本处理；保存不含凭证的协议摘要，标明真实覆盖与受控补充的差别。
4. 检查多调用响应和配额耗尽后无工具最终请求；确认实际出站请求移除 tools，不能仅设 tool_choice。
5. 验证 thinking/reasoning_content、取消及处理期限；记录成功、接口拒绝或未能触发的具体结果。
6. 采集模型、工具与编排耗时并给出采用 SDK 或同构手写方案的依据；若存在兼容阻塞，提供最小复现和替代验证。
7. 交付诊断命令、脱敏证据与退出结论；核对其接口能接入现有分句/演出和取消边界。

## Verification

独立真实云诊断；供应商不能稳定触发的组合由之后的协议 fake 测试补足，证据类别分开。

每项结论注明环境、输入、结果与证据类型。模拟通过不能代替真实接口或浏览器观察；故障和未验证项须保留。完成本票时同步其使用说明与验证命令。
