# 12：按会话和回合查询结果、失败与耗时

**What to build:** 维护者用查询命令找到某轮输入、回答、状态和耗时；数据库是终态依据，附加 JSONL 写入失败不会让用户已完成的问答重做。

**Blocked by:** #11 保证完整回合提交、取消与重提的一致性

**Status:** draft — 待任务粒度、依赖和发布载体审阅

**Spec coverage:** OB-01、OB-02、OB-03、OB-04、OB-06、AC-04

**User stories:** US-18、US-35、US-36、US-37

## Acceptance criteria

- [ ] 每轮具有可关联的会话、回合、开始/终止时间、输入输出、状态、原因及阶段耗时。
- [ ] 成功、失败、取消与进程中断能区分；未完成轮不伪装为普通对话消息。
- [ ] 可按会话或回合查询，找不到记录时有明确结果；顺序稳定。
- [ ] 工具审计能区分实际执行与拒绝，尚无工具的回合显示零次；下一阶段接入真实尝试。
- [ ] 服务端首字、首音就绪和浏览器实际首音分别记录，不跨时钟直接相减。
- [ ] JSONL 失败产生可诊断告警，不撤销成功事务、不重试已完成问答。
- [ ] 记录不含云密钥、共享口令或未经脱敏的连接地址。

## Implementation steps

以下细项与上一级任务清单中的 12.x 一一对应；进度统一在该任务清单记录，本票验收项用于确认行为。

1. 完善回合与阶段事件记录，覆盖成功、失败、取消和启动恢复的中断；通过公开查询验证各终态及关联标识。
2. 实现按会话/回合查询的命令入口和稳定顺序；验证已有、空结果与非法参数的可解释输出。
3. 建立工具尝试审计出口，区分实际执行和拒绝原因；通过受控记录验证配额统计不会混入拒绝项。
4. 接入基线已有的三类延迟测量及浏览器上报；验证缺失实际播放事件时不伪造首音数值。
5. 实现 JSONL 附加出口和失败告警；注入写入失败，验证 SQLite 成功事实与用户历史保持不变且不再调用云。
6. 用合成哨兵验证敏感字段脱敏，并添加查询行为用例；确认日志没有完整带口令 URL。
7. 补齐审计命令、字段口径与排障示例；执行示例并核对输出可关联到真实完成或失败的回合。

## Verification

调用真实查询命令并读取临时数据库中的事实，结合 WS 事件；JSONL 出口故障只在外部写入边界注入。

每项结论注明环境、输入、结果与证据类型。模拟通过不能代替真实接口或浏览器观察；故障和未验证项须保留。完成本票时同步其使用说明与验证命令。

## Scope boundary

不引入完整遥测平台；JSONL 不承担业务事务或唯一审计事实。
