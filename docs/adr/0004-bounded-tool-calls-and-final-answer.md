# 按工具实际执行次数封顶并保证收尾回答

2026-10-24，确认每个对话回合最多实际尝试 3 次工具，失败尝试也计入；达到上限后使用已有结果给出最终回答，信息不足时明确说明不足。课程中的“3 次工具调用”与“3 个模型生成步骤”采用不同计数口径，因此本项目选择前者，最终回答的生成不计作工具调用。

执行层负责限制实际调用次数，收尾阶段不再提供可执行工具。不能只用 SDK 的生成步数控制替代调用配额，也不能仅依赖模型遵循提示词。Vercel AI SDK 6 的一步是一次模型生成，一个步骤可能包含多个工具调用；MiMo 官方文档目前只保证 `tool_choice: auto` 的行为，因此移除收尾阶段的工具定义以及实际次数限制，均需进入后续兼容性验证。

查询期间向用户显示“查询中”，不播报工具查询过程中的垫话；取得结果后才播放有效回答，仍按句播放。记录响应速度时不能把查询状态或过渡语作为有效回答。工具阶段与回答阶段如何保持标签正确、流式输出以及合理延迟，是后续 spike 的验收内容，当前尚未实测。

延迟验收保留“相对基线增加不超过 500ms”作为优化目标，在本机同模型、同条件下分别记录首个有效文字、首段声音和工具耗时。若超标，先区分模型、网络、编排和 SDK 的影响，再决定是否改为手写循环；不直接将作者约 0.9 秒当成本机基线，也不把超过目标本身当作 SDK 不兼容的结论。

M0 仅注册时间探针。小糖可以依据模型已有知识聊基础规则和历史背景，拿不准时说明；实时比分、赛程、当前积分必须说明尚未接入实时查询。提示词需与当前注册能力一致，知识检索和实时数据工具分别在后续里程碑接入。
