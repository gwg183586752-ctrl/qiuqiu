# 录音、标签与冰糖语音验证

2026-10-25，Windows 本机、Node 22.20.0、Chrome；MiMo 按量 API，原有方案保留。密钥只在后端，报告不含认证头或完整连接 URL。

## 实际契约

- 浏览器 AudioWorklet 采集 PCM16、单声道、16kHz，生成真实 RIFF/WAVE 头；服务端验证编码、长度、采样参数与波形幅度。配置录音最长 30 秒、处理总期限 90 秒，WS 最大载荷 8MB。开始后等待首个采样再开放结束按钮；结束后停止媒体轨道。
- ASR 使用 `mimo-v2.5-asr`，WAV 裸 Base64，`input_audio.format=wav`，中文识别。模型使用 `mimo-v2.6-flash`，显式关闭 thinking，输出最多 512 tokens。
- TTS 使用 `mimo-v2.5-tts`、`voice=冰糖`，服务按 SSE 返回 Base64 PCM16LE 单声道 24kHz；适配器验证后封装 WAV。中文语气作为 user 指令，assistant 承载要朗读的纯文本。
- 分句串行合成，只有一条合成链，天然有界并保持序号。媒体实际 `playing` 事件驱动字幕和演出；生成完成不等于播放完成。激活后按序播待播内容，队列耗尽且完成事件到达后才允许录音。

## 已执行结果

真实 CLI 运行 `cloud:check -- --real --speech-fixture`，合成“我喜欢阿森纳，请陪我聊聊足球。”得到 145964 字节、3.04 秒语音，ASR 准确识别相同内容，随后生成回答并完成冰糖合成。该轮 ASR 735ms、首个有效文字 1512ms、首音就绪 3215ms。时间问题的 2.08 秒输入也成功识别，基线如实说明看不到实时时间。以上是独立真实云证据，用户实际等待以浏览器采样为准。

协议测试覆盖跨块表情、动作及语气标签、未知标签、连续标点、末尾无标点，验证口播与字幕纯文本一致。连续标点原会产生单独“！”语音片段，回归先失败后修正为不合成纯标点片段。六条课程演出规则保留，未知标签不执行。

故障验证覆盖无声、超长与错误 WAV 在云调用前拒绝；识别超时释放忙碌状态；合成失败返回已形成的纯文字、不给成功完成事件；SQL 第二条消息及成功终态注入失败均回滚，不进入续聊上下文。播放器错误会清理媒体并重新连接，恢复会话不重播旧声音。

浏览器测试覆盖麦克风拒绝后的提示和恢复、结束后轨道停止、权限允许的真实编码、采样就绪、半双工、字幕按实际声音开始显示、激活恢复以及接管停止播放。四动作通过固定 fake 波形分别观察并截图，不将这些波形当作冰糖语音。

## 仍需分别说明的证据

真实浏览器基线/Agent 报告保留其输入来源为“真实 MiMo TTS fixture 经模拟麦克风”，不是物理麦克风。真实麦克风、扬声器音量和主观音色听感应在最终本机交接中单列；没有人工核对时不标为已验证。

排障顺序：允许本站麦克风权限；确认 Windows 输入设备和未被独占；点击“开启声音”；检查系统输出音量；只用本机回环地址访问；若云认证/模型权限不可用，核对后端 `.env`，无需在聊天中发送密钥。响应流不完整或期限耗尽会失败终止，本轮不作为完整问答恢复。
