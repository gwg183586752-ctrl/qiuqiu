# 原生存储与恢复验证

日期：2026-10-24。实际组合：Windows x64、Node 22.20.0 / ABI 127、better-sqlite3 12.11.1、SQLite 3.53.2、sqlite-vec 0.1.9。精确依赖见清单与锁文件。

```powershell
npm run storage:check
node --experimental-strip-types --test tests/storage.test.ts
```

真实诊断结果：关系记录跨关闭/重开保持一致；1024 维向量返回 rowid=1、distance=0，符合已知样本；结构版本 2。此结果使用真实原生库，没有 mock 驱动或向量查询。

5 项 CLI 行为验证通过：

1. 连续两次运行诊断，跨重开记录与向量近邻均符合预期。
2. 指定不存在的扩展路径时，只将向量能力标记降级，关系写读仍通过。
3. 结构版本 999 被拒绝，数据库文件的 SHA-256 不变。
4. 在迁移已创建部分对象后制造冲突，整个事务回滚，原数据库文件的 SHA-256 不变。
5. 从版本 1 升到 2，原历史摘要和消息数量不变；新增知识块与实体为空、消息打断字段存在。保持源连接开启并写入 WAL 后，一致性备份、恢复文件的历史摘要仍与当前源数据一致。

使用说明与真实维护命令见 README 的存储段落。备份与恢复拒绝覆盖已有目标；不使用复制活动主文件来代替 SQLite 一致性备份。

期间修正了一个实际兼容问题：better-sqlite3 将普通 JavaScript number 按浮点参数绑定，而 vec0 主键要求整数，因此诊断种子行号使用 BigInt。修正前诊断明确报告降级，修正后真实查询通过。
