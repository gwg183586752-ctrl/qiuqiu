# 物理输入排查与回归

2026-10-25。原始用户反馈是结束录音后提示“没有听到有效声音”，因此故障发生在浏览器采样幅度校验，尚未调用 ASR。

按 `diagnosing-bugs` 的单变量诊断思路，先确认默认设备，再检查系统静音与音量，最后对照实际采集流。Windows 只读检查结果为默认 Realtek、未静音、音量 100%；页面展示实际 `MediaStreamTrack.label` 后发现录音流为入梦虚拟音频。用户明确选 Realtek 后实际流恢复，后台有 completed 语音回合，用户确认声音清楚。

没有降低静音阈值，也没有用固定识别文本掩盖问题。新增显式 `deviceId`、当前设备、录音音量条和可恢复提示。录音结束、失败、接管时仍释放媒体轨道，设置入口在录音期间禁用，不创建后台常开麦克风。

公开浏览器回归模拟“系统枚举默认别名为真实设备，但浏览器实际默认流无声”的情况：第一次失败且零提交；切换真实设备后音量条变化、WAV 成功提交且完成回复。先红后绿的命令为 `npm run test:browser -- --reporter=line --grep '默认输入无声'`。另已运行全量 14 项浏览器回归通过、类型检查与构建通过；不把模拟设备切换用例当作物理语音证据，真实设备结果另见第 18 份记录。

Chrome 内部设置页被浏览器工具的 URL 策略阻止后，采用当前应用标准媒体 API 的可见设备选择完成排查，没有通过其他方式读取或修改内部浏览器设置。无临时调试日志或原始录音落盘。
